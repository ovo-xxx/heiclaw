# 部署风险与我们不保证的部分

HeiClaw 是 PicoClaw 的品牌化版本。这一页讲的是把它跑起来时的真实风险：一套部署暴露了什么、
这套软件**不自带**哪些保护、以及一个晚上能做完的规避手段。放到网络上之前先读完。

## 我们不保证什么

MIT 许可证已经写了：软件按"现状"提供，不含任何明示或暗示的保证，作者不对使用后果负责。
在这个基础上，作为这个品牌化版本的维护者，我们再说明白一次：

- 这份代码**没有做过安全审计，也没有做过渗透测试**。
- 没有漏洞赏金，没有协调披露流程，没有响应时限，出了事没有赔偿。
- 它是为**单人自托管**做的。多租户、对外售卖、或者"别人拿到访问权就会让你或第三方损失钱和数据"的
  用法，都不在这套东西的设计范围内。

## 一套部署握着什么

下面这些东西在同一台机器上，隔着同一个登录页：

| 资产 | 位置 | 对攻击者的价值 |
| --- | --- | --- |
| 一个 shell | 面板里的网页终端，以及 agent 能调用的所有工具 | 以服务身份执行代码 |
| 模型 API Key | `.security.yml`，按 `model_name` 分条 | 你的钱和额度 |
| 全部对话记录 | 工作区里的 `sessions/*.json` | 你的秘密，明文存放 |
| 长期记忆 | 工作区里的 `memory/MEMORY.md` | 你让助手记住的东西 |
| 各渠道凭据 | 配置里的微信/钉钉/IRC 等 token | 你的账号 |

服务运行身份就是爆炸半径。这套东西并不阻止你把 launcher 以 root 跑，而 root 服务意味着面板被突破 =
整机被拿下。上线前先确认自己的 unit 文件（`systemctl cat <服务名> | grep User=`），别以为已经在沙箱里。

## 四条真实的出事路径

1. **有人进了面板。** 网页终端加上 agent 的工具，对任何能通过鉴权的人来说就是远程 shell。
   如果 launcher 监听在可路由网卡上，互联网和这个 shell 之间就只剩你自己放的那层鉴权。
2. **agent 被骗。** 一个有 shell、又不需要逐条确认的 agent，会去执行它认为自己被要求执行的东西。
   藏在网页、邮件附件、仓库 README 或粘贴日志里的指令，是现实中"机器自己干了坏事"最可能的来路。
3. **能访问它的机器被别人用了。** 跑过 launcher 的笔记本、还留着面板会话的浏览器，和那套部署是同一份凭据。
4. **Key 泄露。** 供应商的 key 长期有效，又很少设额度。

## 这套软件不自带的东西

以下是软件本身的性质，不是某台服务器的偶然：

- **没有权限隔离。** 这里没有专用服务账户、没有容器、没有 seccomp/AppArmor 策略，要自己加。
- **没有审批门。** 工具调用和 shell 命令不需要人逐条确认。
- **网页终端默认开着。** 它是最省事的工作方式，也是最省事的失守方式。
- **本地信任模型。** 能登录面板的人就被当成主人。应用内没有按用户授权、没有角色、没有第二因素——
  那些都属于你前置的鉴权层。

## 不重做架构也能降风险

按"每分钟换到的安全量"排序。

**暴露面**

- launcher 只绑回环。绝不 `--host 0.0.0.0`，绝不让面板端口出现在公网。
- 前面放真正的鉴权（身份提供方 + 反代鉴权一步），只走 HTTPS，只用一个你自己控制的域名。
- 主机防火墙只开 SSH（仅密钥登录，`PasswordAuthentication no`）、80、443，其余全关。
- 不要把地址发出去。每一个知道地址的人，都是你审计不到的攻击面。
- 远程只需要聊天的话，就把线上终端关掉，终端只在本地用。

**凭据**

- 给这套部署**单独**的供应商 key，设消费上限和额度，不要用账号主 key。泄露一把有上限的 key
  是一个下午的事，泄露主 key 是一周的麻烦。
- key 放 `.security.yml`（0600），不要写进 `config.json`，不要提交，不要出现在截图或共享日志里。
- 不要把面板密码存成明文文件放在会同步的目录里。密码管理器不是可选项。
- 在不是你自己的机器上用完面板，记得退出登录。

**agent 本身**

- 把外部内容当敌意输入：网页、附件、issue、粘贴的日志都可能夹带指令。开着终端的时候，
  不要让它"去读这个链接"，除非它读出来的话你也敢直接执行。
- 对话里不要放你不打算说出口的秘密：会话文件是明文的。
- 任务用得上更便宜或更严格的模型时，就按会话把模型钉住。

**机器**

- 笔记本开整盘加密、锁屏，需要共用这台机器的人另建一个本地账户。
- 面板用独立浏览器配置：不保存密码、不装能读页面的扩展、不同步那个会话 Cookie。
- 工作区和 `.security.yml` 做**加密**备份，并且演练过恢复——恢复路径比"备份存在"重要得多。

**出事之后**

1. 先轮换供应商 key，那是钱。
2. 停服务；因为绑在回环，停掉不影响别的东西。
3. 改鉴权密码，并在身份提供方吊销已有会话。
4. 查反代的访问日志看被请求了什么，查 launcher 日志看执行了什么。
5. 假定工作区已被读过：对话里出现过的东西一律轮换。
