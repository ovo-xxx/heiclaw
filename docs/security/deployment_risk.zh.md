# 部署风险与我们不保证的部分

HeiClaw 是 PicoClaw 的个人品牌化版本。这一页写的是真实风险：这套部署到底把什么暴露在外面、
我们**明确没有**加固哪些地方、以及一个晚上能做完的规避手段。挂域名之前先读完。

## 我们不保证什么

MIT 许可证已经写了：软件按"现状"提供，不含任何明示或暗示的保证，作者不对使用后果负责。
在这个基础上，作为这个品牌化分支的维护者，我们再说明白一次：

- 这份代码**没有做过安全审计，也没有做过渗透测试**。
- 没有漏洞赏金，没有公开披露流程，没有响应时限，出了事没有赔偿。
- 这是**单人自用**的部署。多租户、对外售卖、或者"别人拿到访问权就会让你或第三方损失钱和数据"的
  用法，都不在这套东西的设计范围内。

## 一套部署实际握着什么

下面这些东西在同一台机器上，而且隔着同一个面板：

| 资产 | 位置 | 对攻击者的价值 |
| --- | --- | --- |
| 一个 shell | 面板里的网页终端，以及 agent 能调用的所有工具 | 以服务身份执行代码 |
| 模型 API Key | `.security.yml`，按 `model_name` 分条 | 你的钱和额度 |
| 全部对话记录 | `/var/lib/picoclaw/workspace/sessions/*.json` | 你的秘密，明文存放 |
| 长期记忆 | `workspace/memory/MEMORY.md` | 你让助手记住的东西 |
| 各渠道凭据 | 配置里的微信/钉钉/IRC 等 token | 你的账号 |

服务运行身份就是爆炸半径。我们的服务器上 launcher 以 **root** 运行，所以面板被打通 = 整机被拿下。
这是记录在案的选择，不是疏忽。

## 四条真实的出事路径

1. **有人进了面板。** 互联网和 root shell 之间只有前置鉴权那一层（Caddy `forward_auth` → Tinyauth）。
   launcher 本身绑在 `127.0.0.1`，外部直连不到 —— 请一直保持这样。
2. **agent 被骗。** 一个有 shell、有完整权限的 agent 会去执行它认为自己被要求执行的东西。
   藏在网页、邮件附件、仓库 README 或粘贴日志里的指令，是现实中"电脑自己干了坏事"最可能的来路。
3. **别人用了你这台机器。** 跑过 launcher 的笔记本、还留着面板会话的浏览器，和那个域名是同一份凭据。
4. **Key 泄露。** 供应商的 key 长期有效，又很少设额度。

## 我们没做的事，以及它的代价

这次部署明确决定的几件事，写下来免得以后有人意外：

- **不做权限隔离。** 服务仍是 root，没有专用低权限用户、没有容器、没有 seccomp/AppArmor 策略。
  面板被突破就是主机被突破。
- **不做操作审批。** 工具调用和 shell 命令不需要人逐条确认。
- **网页终端是开着的。** 它是最省事的工作方式，也是最省事的失守方式。
- **本地信任模型。** 能登录面板的人，就被当成你本人。

## 不重做架构也能降风险

按"每分钟换到的安全量"排序。

**暴露面**

- launcher 只绑回环。绝不 `--host 0.0.0.0`，绝不让 `:18800` 出现在公网。
- 前面放真正的鉴权（Tinyauth/OIDC），只走 HTTPS，只用一个你自己控制的域名。
- 主机防火墙只开 22（仅密钥登录，`PasswordAuthentication no`）、80、443，其余全关。
- 不要把地址发出去。每一个知道地址的人，都是你审计不到的攻击面。

**凭据**

- 给这套部署**单独**的供应商 key，设消费上限和额度，不要用账号主 key。泄露了一把有上限的 key
  是一个下午的事，泄露主 key 是一周的麻烦。
- key 放 `.security.yml`（0600），不要写进 `config.json`，不要提交，不要出现在截图或共享日志里。
- 不要把面板密码存成明文文件放在会同步的目录里。要存就存进密码管理器，别放磁盘。
- 在不是你自己的机器上用完面板，记得退出登录。

**agent 本身**

- 把外部输入当敌意内容：网页、附件、issue、粘贴的日志都可能夹带指令。开着终端的时候，
  不要让它"去读这个链接"，除非它读出来的话你也敢直接执行。
- 对话里不要放你不打算说出口的秘密：会话文件是明文的。
- 远程只需要聊天的话，就把线上终端关掉，终端只在本地用。

**机器**

- 笔记本开整盘加密、锁屏，需要共用这台机器的人另建一个本地账户。
- 面板用独立浏览器配置：不保存密码、不装能读页面的扩展、不同步那个会话 Cookie。
- `workspace/` 和 `.security.yml` 加密备份，并且**验证过能恢复**——恢复路径比"备份存在"重要得多。

**出事之后**

1. 先轮换供应商 key，那是钱。
2. 停服务（`systemctl stop picoclaw-launcher`）；因为绑在回环，停掉不影响别的东西。
3. 改鉴权密码，并在身份提供方吊销已有会话。
4. 查 `/var/log/caddy/*-access.log` 看被请求了什么，查 launcher 日志看执行了什么。
5. 假定工作区已被读过：对话里出现过的东西一律轮换。
